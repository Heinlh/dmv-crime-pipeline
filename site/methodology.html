Methodology // corrections applied to published data

Methodology

Published crime data misleads in specific, measurable ways if you aggregate it straight. Three corrections are applied here, and every number on this page is measured from the current warehouse on each daily run, not asserted once and left to rot.

1. Aoristic timing: the hour-of-day chart is usually wrong

Almost every "when does crime happen" chart plots the offense start time. For offenses nobody witnessed, that timestamp is not when the crime happened; it is when the victim was last there. Park at 8 AM, return at 6 PM to a broken window, and the agency records a window from 8 AM to 6 PM. Plotting the start says the crime happened at 8 AM, which is really a chart of commuter schedules.

Aoristic weighting spreads each incident's single unit of probability across the hours its window actually covers, in proportion to how much of each hour is covered. A window of a day or longer is uniform across the clock by construction. Both curves below contain exactly the same total number of incidents; only the placement differs.

Which offenses are most distorted

2. Reporting delay: the last few days are always fake-declining

A report reaches the published dataset days after the offense. So when you count incidents by the date they happened, the most recent days are not finished yet, and every such chart bends downward at the right edge. That decline is an artifact of the calendar, not a drop in crime, and it is the single easiest way to accidentally publish a false good-news story.

The fix is the same arithmetic epidemiologists use for nowcasting. Using only occurrence days old enough to be complete, measure how the reporting delay is distributed. That gives, for a day of any age, the share of its eventual reports that should have arrived by now. Dividing the observed count by that share estimates the eventual total, with an interval that widens as completeness falls.

3. Alert signals: controlling false alarms across hundreds of series

The Daily Brief flags unusual activity per neighborhood and category. That is hundreds of separate statistical tests every single day, and this is where crime "spikes" are usually manufactured: run enough comparisons and some always look extreme. At a naive 5 percent threshold, roughly one test in twenty fires on pure noise, so a few alarming-looking alerts every day are guaranteed even if nothing whatsoever changed.

Each series is compared against its own same-weekday baseline using a Poisson tail probability, then all of the day's p-values go through a Benjamini-Hochberg correction, which bounds the expected share of false alarms among the signals actually reported. Series whose typical volume is too low to distinguish a spike from arithmetic are not tested at all.

The honest way to check a detector with no ground truth is calibration, not a precision number: generate counts from each series' own baseline so that every series is null by construction and no real spike exists, then run the detector and count what fires. Anything it reports there is a false alarm by definition.

These signals describe reported data. They are not predictions, and nothing here forecasts where crime will occur.

What is not corrected

  • Aoristic weighting needs published end times, so it covers only the sources that publish them. The rest are shown as start times, which is what the agency gave us.
  • Nowcasting needs published report dates, so it covers only the sources that publish them. Both scopes are printed above, measured from the data.
  • Reported crime is not total crime. No statistical correction can recover offenses nobody reported, and nothing here attempts to.
